# 0246 - Map step: per-firm structured extraction, corrective re-search, evidence matrix, behavior decided by code

Issue: #246    Role: TL    Spec: specs/answer-citations.md (also specs/retrieval.md for the re-search,
specs/filings.md for the `config/metric_definitions.yaml` fields, specs/ui.md for the trace line)

Binding: ADR-021 rules 0-8 (rules 1, 2, 3, 6, 7 are built here), the ADR-012 / ADR-018 / ADR-019 /
ADR-020 amendments, CLAUDE.md ground rules and "Paid API calls". Builds on #245 (merged, PR #255:
`SubQuestion`, `Plan.searched`, `planner.corrective_search`) and #242 (DeepSeek path). #247 (reduce
step) reads the `EvidenceMatrix` defined here; #248 (per-call cache for every call type, cost, app
stages) builds on the map cache added here.

## Goal
After retrieval, one **structured extraction** call per firm (plus one for the research passages),
run in parallel, fills an **evidence matrix** (firm x aspect): every cell is labelled `fact`,
`not_disclosed`, `not_found` or `different_quantity`, with items that cite only chunks retrieved for
that sub-question. A `not_found` sub-question gets one **corrective re-search** (CRAG) and one
re-extraction. Code, not the model, then decides the answer behavior (ADR-021 rule 1), marks
comparability from `config/metric_definitions.yaml` (rule 2) and builds the gap texts and caveats.
The planner moves to `plan-v3.1`: each aspect carries a required `proxy` flag, so an aspect that asks
for a stand-in (the closest disclosed figure) can never make the behavior `answer` (section 3a).
Until #247 lands, the map is **off by default in the app** (`MAP=off`; the eval turns it on
explicitly): with `MAP=on`, `ask()` builds and logs the matrix; either way the interim single answer
call (prompt v4.1) stays the answer the user sees.

## Industry terms used
Map-reduce (this issue = map), structured extraction / slot filling (one call per entity),
evidence matrix (a comps table, firm x aspect), corrective retrieval (CRAG: retrieve again with
widened words when the extraction finds nothing).

## 1. Units of work
- **Map call specs** (`extract.map_calls(q, plan, hits)`): the plan's sub-questions grouped by
  `sq.entity` in `firm_scope` order (`None` = theme mode, call id `map.all`); one call per group
  that has at least one passage (`map.<ENTITY>`), plus `map.research` when there are research
  passages (`part_id == "research"`). The input of a firm's call is that firm's passages, grouped
  under the sub-question that kept them (#245 D8: a chunk is kept once, under its first
  sub-question).
- A firm whose sub-questions kept **no** passage (e.g. Q19's MS and RJF after the floor across
  competitors) gets **no call**: code writes `not_found` cells (`source: "code"`, reason "no passages
  retrieved"), which then go to the re-search.
- Research cells: one per aspect, id `<aspect>.research`, entity `None`, role `research`.
- Passage mode (`passage_plan`, one Part `p1`) and `Plan.from_parts` plans work the same way: a
  sub-question with no single entity groups under `all`.
- No hits at all (empty retrieval, unsearchable question): no call; every cell `not_found` by
  code; no re-search for an unsearchable question.

## 2. Extraction schema (`extract.extraction_schema(spec, strict)`), strict on every provider
One object per call; every property required, `additionalProperties: false`, no `anyOf`/`null`
(empty string = none), no array limits except Anthropic's `minItems: 1` on `cells`:
```
{"cells": [cell]}
cell = {
  "subquestion_id": string, enum = the call's cell ids (e.g. ["a1.EDJ","a2.EDJ"] or ["a1.research"]),
  "label": string, enum ["fact","not_disclosed","not_found","different_quantity"],
  "items": [item],
  "differs_because": string,          # "" unless different_quantity
  "reason": string,                   # one sentence: why this label
  "derivation": {"operation": string enum ["","ratio","sum","difference"],
                 "inputs": [{"subquestion_id": string enum (the call's ids), "item": integer}]}
}
item = {"text": string, "quote": string, "chunk_ids": [string], "value": string, "unit": string,
        "period": string, "scope": string, "definition": string}
```
- **anthropic**: tool `submit_extraction`, `strict: true`, `tool_choice auto` (as the answer and the
  planner, #232); `anthropic.transform_schema` must leave it unchanged (test).
- **openai**: `response_format json_schema strict` with the same schema minus `minItems`.
- **deepseek**: `llm.deepseek_tool_request(EXTRACT_TOOL, ..., schema(strict=True), ...)` on `/beta`,
  thinking per `DEEPSEEK_THINKING` (default on: `tool_choice auto`; off: forced function). Nested
  objects, `integer` and `enum` re-checked against DeepSeek's strict-mode docs at build (WebFetch of
  the tool-calls guide); if one is not supported, that field becomes a plain string / code-validated
  on that path and the PR says so. A 400 is handled as in section 5.
- Output caps (`extract.extract_max_tokens(provider)`): anthropic / openai 20000 (= `llm.MAX_TOKENS`,
  under the SDK's 21,333 non-streaming limit); deepseek 64000 thinking on, 20000 off (=
  `llm.DEEPSEEK_MAX_TOKENS`). The map cap joins the map cache key directly; `llm.request_version` is
  **not** changed, so every existing plan and answer cache key stays valid.
- Pydantic models `MapOutput` / `CellOut` / `ItemOut` validate the tool input on every path (replays
  included).

## 3a. Proxy aspects: planner `plan-v3.1` (blocking 2, TL decision B2)
Plan-v3 tells the planner that "a figure that may not be disclosed also asks for the closest
disclosed figure, as its own aspect" (Q24's saved plan: a2 "total client assets, as the closest
disclosed numerator", a3 "advisor headcount, as the closest disclosed denominator"). Extract-v1 would
label the closest figure `fact` for such an aspect, and rule (a) would then answer Q29, Q30 and
Q33-Q35, which stay `gap_with_adjacent` (ADR-021 bank audit). A closest figure is not the asked
quantity. Enforced in two places:
- **Planner `plan-v3.1`** (`PLANNER_VERSION = "plan-v3.1"`, `planner.py`): each aspect gets a
  required boolean `proxy` in all three schemas (`{"type": "boolean"}`, strict-safe on every path).
  Prompt rule added: "proxy: true when the aspect asks for a stand-in for what the question asks (the
  closest disclosed figure, a numerator or denominator to compute it, the nearest measure); false for
  everything the question asks itself." `Aspect.proxy: bool = False`; `validate_plan`: missing or not a
  boolean -> False with a note; `rules_plan` -> False; `Plan.to_log()` keeps it (in `aspects`). The
  plan cache key changes through `PLANNER_VERSION` (no v3 plan is reused). The rest of v3 (literal
  aspects, firms, kinds, metric, no cap) is unchanged.
- **Code (`matrix.py`)**: a cell of a proxy aspect never fires rule (a). Its counting items feed the
  adjacent side: for the behavior it counts as a related quantity (rule b), for #247 its items are
  adjacent items. A proxy aspect gets no aspect-level "does not support" gap and no per-cell gap (the
  asked aspect carries the gap). Proxy cells may still be **derivation inputs** (Q24: a1.EDJ derived
  from a2.EDJ / a3.EDJ), and a `derived` cell of a non-proxy aspect fires rule (a).
- **Prompt (extract-v1)**: the proxy rule is one constant, `extract.PROXY_RULE`, used verbatim in
  the firm prompt and the research prompt (approval condition 1, round-2 note 3); its text is the
  paragraph "Only the quantity a sub-question names ..." in the section 3 draft. For a `[proxy]`
  sub-question the fact is the figure the sub-question's own text names (a numerator, a denominator
  or the closest measure, e.g. total client assets or the firm's count of financial advisors), as the
  firm reports it; a figure of a different measure (all employees, full-time equivalents,
  compensation expense, client firms on a platform) is `different_quantity`. The code rule (a proxy
  never fires (a)) holds whichever label the model picks. The user message marks proxy sub-questions
  `[proxy]`. The real-check report says whether a2.EDJ and a3.EDJ came back `fact`.

## 3. Prompt `extract-v1` (`EXTRACT_VERSION = "extract-v1"`, `src/cee/answer/extract.py`)
System prompt draft (final wording at build, same rules; no question ID, no question text, no
`passes_if` text: the existing 6-word-run test is extended to it):
```
You extract evidence about one firm from passages of its documents, for a question about
wealth-management firms. Code has split the question into sub-questions; return exactly one cell
for each sub-question listed. You do not answer the question and you do not compare firms: code
and a later step do that.

Use only the passages below. Never use what you know from elsewhere, never estimate, never compute
a figure.

Label each cell:
- fact: a passage states what the sub-question asks for this firm, in full or in part. Partial is
  still a fact (some periods, a narrower group or sample, one of several figures); the item says
  what it covers (period, scope).
- different_quantity: no passage states the asked quantity, but one states a different, related
  quantity: a wider unit that contains the asked one (a parent company, a segment that also holds
  other businesses), a different measure (all employees or full-time equivalents for advisors,
  compensation expense for a payout grid or a headcount, client firms on a platform for the firm's
  own advisors, a regulatory form's label for a business metric), or an industry figure for a firm's
  own figure. Put it in items and say in differs_because how it differs from what is asked.
- not_disclosed: the passages show the firm does not report it (they say so, or they report the
  surrounding figures without it).
- not_found: the passages say nothing about it.
Only the quantity a sub-question names is a fact for it; a figure that only resembles it is never a
fact. A sub-question marked [proxy] names a stand-in figure (a numerator, a denominator or the
closest measure to what the question asks, such as total client assets or the firm's count of
financial advisors): that named figure, as the firm reports it, is a fact. A figure of a different
measure than the one named (all employees, full-time equivalents, compensation expense, client
firms on a platform) is different_quantity, with differs_because. When unsure between fact and
different_quantity, choose different_quantity and say why.
(This paragraph is `PROXY_RULE`, the same text in the firm and the research prompt.)

Items (fact and different_quantity only), one per figure or statement; a series is one item per
period:
- text: one sentence stating what the passage says, attributed to the firm, in the passage's terms;
- quote: the exact words of the passage that support it, copied, at most about 300 characters;
- chunk_ids: the ids of the passages quoted, only ids listed below;
- value: the figure as printed ("20,425", "$1.2 billion"), "" when the item states no figure;
- unit: what is counted or measured ("financial advisors", "USD"), "" when no figure;
- period: "YYYY-MM-DD" for a point in time, "YYYYQn" for a calendar quarter, "FYYYYY" for a fiscal
  year, "YYYY" for a calendar year; "" when not stated or no figure;
- scope: the part of the firm the figure covers as the passage says (a segment, a country), "" for
  the whole firm;
- definition: the firm's own definition of the quantity when a passage gives one, quoted; else "".
The firm's own definition of a metric, quoted from a passage, is a fact for a sub-question that asks
how the firm defines or reports it.

Derivation: when a sub-question asks for a quantity the firm does not report but which follows from
figures in your other cells (a ratio, a sum or a difference) for the same period and scope, label it
not_disclosed and set derivation to the operation and its inputs (sub-question id and item number,
counting from 0; numerator first). Do not compute it: code checks and computes it. Otherwise the
operation is "" and inputs is empty.

Positions others hold about the future (executives, analysts, surveys) are facts when the passage
attributes and dates them; never add a forecast of your own. Write nothing about what any firm
should do.
Return the cells by calling the {tool} tool.
```
- Research call: the same prompt plus a paragraph: "These passages are industry research, not one
  firm's documents; the cell ids end in `.research`. A research figure is a fact for an aspect about
  the industry, clients or advisors in general; for an aspect about a named firm's own figure it is a
  different_quantity (an industry figure, not the firm's disclosure)."
- User message: question; "Firm: <name> (<ID>)" (or "Industry research" / "All sources"); the time
  window line when the question has one (as prompt v4.1, `llm.window_line`); the sub-questions, one
  line each `<id> [kind, metric, proxy when set]: <aspect text>`; then the passages grouped under each sub-question
  in hit order with `llm._chunk` (`<chunk id=...>` with doc, type, dates, segment); a sub-question
  with no passage of its own says so (`llm.NO_PASSAGES` / `KEPT_ELSEWHERE`, by its pool as #245).
- No configured definition text from `metric_definitions.yaml` goes into the prompt: labels come
  from the passages only (rule 0); bases are applied by code (section 8).

## 4. Parallel calls
- `run_map(q, plan, hits, provider, call=None, concurrency=None, ...)` runs the round-1 specs in a
  `ThreadPoolExecutor(max_workers=concurrency)`; results are put back in spec order, so the matrix is
  deterministic whatever the finishing order.
- Setting `MAP_CONCURRENCY` (env, `Settings.map_concurrency`, default **6** = five firms + research;
  `_positive_int`, so 0 / text is a clear error). Round 2 (re-extraction) uses the same pool size.
- `ProviderStop` (DeepSeek 401 / 402 / 429) in any call: no further call is submitted
  (`cancel_futures`), calls already running finish (and are saved by the eval), then the question
  stops with the plain message, as everywhere since #242. Calls reserved for the round but cancelled
  are not counted as made: the eval reports `calls_made` and `calls_reserved` separately (note 3).
- Any other error inside a call (timeout, 5xx, connection error, an Anthropic / OpenAI 401 or 429,
  which do not become `ProviderStop` on those paths): caught inside the worker, so the round goes on
  and every running call finishes; that call's cells become `failed` with the error (section 5).
- `call` is injectable: default = the real provider call (`extract.call_extract`); the mock provider
  uses `mock_extract` (0 calls); the eval passes its caching wrapper (section 12); tests pass fakes.
- Per-call input check (never silent, no trim): a call whose estimated input (characters / 4) passes
  the provider's context window minus the map cap minus the fixed prompt is not sent; its cells are
  `failed` with reason "input over the model's limit" (not expected: #245's five-firm real plans read
  ~216k-239k tokens in all, about 50k per firm on average, against DeepSeek's 1M window).

## 5. Invalid outputs: saved, never re-rolled
`extract.call_extract(spec, provider, client=None, meta=None) -> dict` raises `llm.ModelOutputError`
(raw payload, `stop_reason`, `usage` kept; DeepSeek `reasoning_content` in `meta`) when:
| Output | Result |
|---|---|
| no `submit_extraction` call (anthropic tool_use / deepseek tool call) | invalid |
| cut at the cap (`max_tokens` / `length`), even when the partial input validates | invalid |
| Anthropic `stop_reason` `refusal` | invalid |
| DeepSeek `finish_reason` not `tool_calls` / `stop` | invalid |
| arguments / content not JSON or not a JSON object | invalid |
| not a valid `MapOutput` (pydantic) | invalid |
| zero cells | invalid |
- The cells of an invalid call become `failed` (code label): no re-search, no re-extraction (that
  would be a re-roll of the same evidence), a named gap (section 9).
- A cell missing from a valid output -> `not_found`, flag `missing_cell` (it goes to the re-search:
  the re-extraction reads new passages, so it is not the same request again). A duplicate cell id ->
  the first kept, note `duplicate_cell`.
- **Failed calls (blocking 3, TL decision B3)**: any exception from the provider call other than
  `ProviderStop` and `ModelOutputError` (timeout, 5xx, connection error, Anthropic / OpenAI 401 / 429,
  a 400) makes that call's cells `failed` with `error = "<ExceptionType>: <message>"`. In the eval
  the call is counted and a `failed_call` record is saved (`invalid: true, failed_call: true, error,
  raw_payload: null, bad_request`, timing), reused on every later run and never re-called, as
  `RealRunner.plan` does. In the app the error is logged in `matrix.calls`. Other calls of the round
  are not affected.
- A 400 (the provider rejects the request, e.g. the schema) is a failed call as above; in the eval
  the run then stops after the round finishes and every record is saved (every planned call would
  fail the same way, as #245's planner rule).
- Every call, valid or not, is logged in `matrix.calls` with id, round, entity, cell ids, chunk ids,
  provider, model, version, `stop_reason`, `usage`, wall time, error.

## 6. Chunk-id check against each sub-question's retrieved set (code, after every call)
- **Retrieved set of a sub-question** S: the passages S kept, plus the chunks S's own search found
  that an earlier sub-question of the same call kept (in S's candidate pool and in the call's input;
  needed because #245 keeps a chunk once, under its first sub-question), plus S's re-search hits in
  round 2. Research cells: the research passages. `search_subquestions` already computes each
  sub-question's `PoolTrace.ids()` (it fills `part_pools` for the eval); it also keeps that same
  value in `plan.pools: dict[str, set[str]]` (not in `to_log()`; the pool size is logged already),
  so there is one mechanism, not two (note 1). `PoolTrace.firm` / `on_theme` record candidates before
  the `exclude` filter, so a sibling-kept chunk is in the pool. Answer turns enter
  `PoolTrace.answers` only after the `exclude` filter, so a sibling-kept answer turn is not in a later
  sub-question's pool and cannot be cited for it: accepted, stated in the spec.
- An item's chunk id outside its cell's retrieved set (another firm's chunk, a chunk the model never
  saw, an invented id) is **rejected**: removed from `chunk_ids`, kept in `item.rejected_ids`, item
  flag `unmatched_citation` (flagged, never silently dropped). An item left with no valid id does
  not count; a `fact` / `different_quantity` cell with no counting item is read as `not_found` for
  the behavior and the re-search (`cell.effective_label`), the model's label kept in the log.
- `quote` must be a substring of one of the item's valid cited chunks (whitespace collapsed, case
  kept); else flag `quote_not_found` (the item still counts; #247 and the PR see the flag).
- `value` is checked against the cited chunks with `validate.number_matches` / `_chunk_values`
  (the answer's number check rules); no match -> flag `number_not_found`; such an item is never a
  derivation input.
- `period` is normalised (`YYYY-MM-DD`, `YYYYQn`, `FYYYYY`, `YYYY`); any other text -> `""` with flag
  `period_unparsed` (unknown period = never the same basis).

## 7. Corrective re-search (CRAG), once per not_found sub-question
- Eligible after round 1: every firm sub-question whose `effective_label` is `not_found` (model
  label, missing cell, rejected citations, or code `not_found` for a firm with no passages). Not
  eligible: `failed` cells, research cells (no sub-question hook), sub-questions of
  `kind == "comparison"` (TL decision D3 below), and any question that is not searchable.
- Each eligible sub-question: exactly one
  `planner.corrective_search(q, plan, sq.id, widen_words(q, sq, as_of), exclude=used)`, where `used`
  = every chunk id already retrieved for the question (all sub-questions, research, earlier re-search
  hits in this loop), so only new chunks come back. Every SQL filter is kept by the hook (#245);
  competitors stay on the theme and under their aspect's floor.
- `widen_words(q, sq, as_of)` (code, deterministic, logged):
  1. registered metric (`aspect.metric`): the firm's `metric_definitions.yaml` entry (MER -> its
     `parent` BAC entry): the `quote`, the `includes` items, and the search phrases written in
     `looked_in` (the text after "full-text search ...:" and inside parentheses), deduplicated;
  2. synonyms come for free: `fts` expands config synonyms from the widened words (`expand_synonyms`);
  3. adjacent periods, as words only (the SQL window is never widened): with a window, the calendar
     quarter before the window start and the quarter of its end ("third quarter 2026", "3Q26"); for
     `kind == "series"` without a window, the four quarters before the as-of date in the same two
     forms;
  4. `strip_neighbours` runs inside the hook (#245), so no neighbour firm phrase is added.
- **Re-extraction**: the sub-questions whose re-search returned at least one hit are re-extracted,
  grouped per firm, one call per firm (`remap.<ENTITY>`), in parallel, over only those
  sub-questions and only their new hits. Sub-questions with no new hit stay `not_found` with
  `researched: true, research_hits: 0` and no call. A re-extracted cell replaces the round-1 cell
  (the round-1 cell kept in `cell.first`); whatever it says is final (no second re-search).
- The re-search hits are matrix evidence only: they are not added to the interim answer's hits, so
  retrieval scoring, `query_log.chunk_ids` and the interim answer are unchanged; they are logged
  under `matrix.research` (id, words, hits, chunk ids).

## 8. Data model (`src/cee/answer/matrix.py`)
```python
LABELS = ("fact", "not_disclosed", "not_found", "different_quantity")   # the model's labels
CODE_LABELS = ("derived", "failed")                                     # set only by code

@dataclass
class Item:
    text: str; quote: str; chunk_ids: list[str]; value: str; unit: str; period: str
    scope: str; definition: str
    rejected_ids: list[str] = []; flags: list[str] = []   # unmatched_citation, quote_not_found,
                                                         # number_not_found, period_unparsed

@dataclass
class Cell:
    id: str                      # sub-question id ("a2.EDJ") or "<aspect>.research"
    entity: str | None           # None: research / theme mode
    aspect_id: str
    role: str                    # named | competitor | all | research
    label: str                   # model label, or "derived" / "failed" (code)
    source: str                  # model | code | mock | reextract
    items: list[Item]
    differs_because: str = ""
    reason: str = ""
    flags: list[str] = []        # missing_cell, duplicate_cell, no_passages, definition_unverified
    derivation: dict | None = None   # model proposal; after code: {operation, inputs, value, formula, ok, why}
    researched: bool = False; research_hits: int = 0
    first: dict | None = None    # the round-1 cell when re-extracted
    @property effective_label   # not_found when no item counts (section 6); else label

@dataclass
class AspectMark:                # comparability per aspect (rule 2)
    aspect_id: str; metric: str | None
    status: str                  # same_basis | different_basis | unverified | none
    firms: list[str]             # firms with counting items
    caveat: str | None           # the standard comparability caveat (different_basis)
    mark: str | None             # "definition unverified" mark (unverified)
    shared_periods: list[str]    # periods every firm with facts reports (same_basis only)

@dataclass
class EvidenceMatrix:
    question: str
    rows: list[str]              # firm ids in firm_scope order, then "research" ("all" in theme mode)
    aspects: list[Aspect]        # from the plan
    cells: dict[str, Cell]       # every sub-question + research cell, in plan order
    marks: dict[str, AspectMark]
    behavior: str | None         # ADR-021 rule 1, decided by code; None = undecided (section 9)
    behavior_reason: str         # which rule fired, e.g. "1a: fact in a1.EDJ, a3.RJF"
    incomplete_note: str | None  # undecided only: the plain "This answer is incomplete ..." text
    gaps: list[dict]             # code-built {cell or aspect id, what, suggested_source}
    caveats: list[str]           # comparability caveats + entity caveats (GWIM), code-built
    calls: list[dict]            # every map / re-map call (section 5)
    research: list[dict]         # every corrective re-search (section 7)
    version: str = "extract-v1"
    def to_log(self) -> dict     # JSON-safe; rows x aspects grid with labels for the log and the PR
    def counts(self) -> dict     # labels per aspect, calls per round
```
#247 reads `cells`, `behavior`, `gaps`, `caveats`, `marks` and the allowed chunk ids
(`matrix.chunk_ids()` = every valid cited id; the reduce may cite only these).

## 9. Code rules
### Behavior (ADR-021 rule 1, with its precedence), `matrix.decide_behavior(m, q, plan)`
Applied in this order; the first that fires decides; `behavior_reason` names it:
1. **(e) forecast request -> `refuse`** (`forecast_request(question)`): the question asks the system
   for its own forecast: a narrow pattern - it starts with forecast / predict / project / estimate,
   or asks "your forecast / prediction", or "what will <x> be / reach in <year> / next year".
   Positions of others (Q16 "what will ... look like") do not match. Tests: no question of the bank
   (Q1-Q35) matches; three synthetic forecast requests match.
2. **(e) normative part -> `answer_with_boundary`** (`normative_question(question)`): the question
   asks what the home firm should or could do. Narrow patterns (note 5), home-firm names and aliases
   from `config/entities.yaml` (`<EJ>`):
   - a modal with the home firm as its subject: "(should|could|can|ought to|must) <EJ> <verb>"
     ("how could Edward Jones replicate", Q12);
   - "should" asking how something should change the home firm: "how should <x> (shape|change|
     influence|guide|inform|drive|affect) <EJ>('s)" (Q19).
   Tests: exactly Q12 and Q19 of the bank match; negatives that must not match: "What should
   investors know about Edward Jones's fees?", "How should clients compare Edward Jones with Morgan
   Stanley?", "What could slow Edward Jones's advisor growth?", "Edward Jones says advisors should
   meet clients yearly."; positives: "Should Edward Jones launch a robo-advisor?", "How can Edward
   Jones win younger clients?". (`validate.is_normative` is for answer sentences and matches no bank
   question.)
3. **(a) any cell holds the asked quantity -> `answer`**: a cell whose `effective_label` is `fact`,
   or `derived` (1d), in any row (research included), on an aspect whose kind is not `comparison`
   **and which is not a proxy** (section 3a).
4. **undecided** (TL decision D5): no fact, and at least one cell is `failed`: `behavior = None`,
   reason "extraction failed for <firms>"; rules (b) and (c) state an absence that a failed
   extraction cannot show. The matrix carries the code-built text `incomplete_note` = "This answer is
   incomplete: the evidence for <firms> could not be extracted (the model output was invalid or the
   call failed). Nothing is concluded about what <firms> disclose." #247 shows the answer plainly as
   incomplete with that text, **never as `refuse`** and never with "The database does not support
   this today". Not in ADR-021's text: recorded in the ADR-021 amendment of this PR (so the PR is
   escalated to the TL for the merge).
5. **(b) no fact, but some cell holds a related quantity -> `gap_with_adjacent`**: a
   `different_quantity` cell, or a counting `fact` cell of a proxy aspect.
6. **(c) else -> `refuse`.**

Comparison-kind aspects (rule 4) are answered by the reduce from the other cells and the marks;
their cells are extracted (a firm's own statement about comparability is evidence) but never decide
the behavior and get no gap of their own. Proxy aspects: section 3a.

### Gaps (code-built text, for #247 to place; spec "Standard wording" gains these rows)
Per cell that is not a counting fact / derived (comparison and proxy aspects excluded), `what`:
- not_disclosed: "<Firm> - <aspect>: not disclosed in the documents searched."
- not_found: "<Firm> - <aspect>: not found in the documents searched." (+ " A second search with
  wider words found nothing new." when re-searched with 0 hits)
- different_quantity: "<Firm> - <aspect>: not disclosed; a different quantity is listed as adjacent."
- failed: "<Firm> - <aspect>: not extracted (the model output for this firm was invalid or the call
  failed)."
Per non-proxy, non-comparison aspect that no row holds (rule 1a): "The database does not support this today: <aspect>
(<firms>)." (<firms> = the aspect's rows, short names). `suggested_source` from
`validate.suggested_sources(entity)`. `<aspect>` = the aspect text without its final period; a
normative aspect text is printed as its id (ground rule 6, as `check_parts`).

### Derivation check (rule 1d + rule 2 within-firm), `matrix.derive(m)`
A model-proposed derivation is accepted only when: every input is a counting item of a `fact` cell
(proxy aspects allowed) of the **same firm**; no input has `number_not_found`; all inputs have the same
non-empty normalised `period` and the same `scope` (case/space-normalised; "" = whole firm); for
`sum` / `difference` the same `unit`; both values parse (`validate.figures`, scale words applied).
Code then computes the value, writes `formula` ("<a2.EDJ#0> / <a3.EDJ#0> = 2,345 billion / 20,425 =
...", inputs as printed) and sets the cell's label to `derived`; a cell whose aspect has no
registered metric also gets the flag `definition_unverified` (rule 2). Otherwise the proposal is kept
with `ok: false` and `why` (e.g. "periods differ: 2026-06-30 vs 2025-12-31"), and the cell keeps its
label. A call's `derivation.inputs` enum lists only that call's own cell ids, and a re-extraction
call sees only its re-searched sub-questions and their new hits, so it cannot reference round-1
items: derivations are proposed in round 1 (inputs from round-1 cells); a re-extraction can propose
one only from its own cells (note 6, documented in the spec).

### Comparability (rule 2), `matrix.mark_comparability(m)`
Per aspect, over the rows with counting items (research excluded):
- **Registered metric** (`aspect.metric` set): each firm's `basis`, `period`, `unit` from
  `metric_definitions.yaml` (MER -> its parent BAC's entry, which is wider: the GWIM caveat still
  applies). Two or more firms, all the same `basis` and `unit` -> `same_basis`, with
  `shared_periods` = item periods every such firm reports (comparison / computation only at those).
  Otherwise -> `different_basis` and the caveat, exactly the spec's standard wording:
  "<Metric>: the firms define it differently (<firm>: <definition>; ...); figures are listed side by
  side and not compared or combined (reporting risk)." <Metric> = the key with underscores as spaces,
  capitalised ("Advisor headcount"); <definition> = the entry's `quote` cut at a word boundary to 160
  characters ("..." when cut) and its chunk id. One firm with facts: `none` (nothing to compare).
- **No registered metric**, and at least one counting item has a `value` (or a `derived` cell):
  `unverified`, mark "<aspect> is not in the metric definitions file; its definition is unverified."
  Never compared or combined across firms; within-firm derivations allowed (above).
- Qualitative aspects (no values): `none`.
- Entity caveats kept: `validate.insert_caveats` logic on the cited items' hits (a MER cell citing a
  BAC GWIM chunk adds "GWIM is not Merrill: ...").

## 14. `scripts/eval_run.py`

  `calls_made` and `calls_reserved` separately (note 3).

  search, map, re-search, re-extraction; no answer call.
