   calls + reused + no_call = 30, list INVALID_OUTPUT if any. Record sha, model, prompt version.
3. **Score R1.** Copy `pack.py` to `cache\ev121\pack.py`, build `cache\ev121\r1-scoring\`, read
   each answer against `passes_if` (four axes, one verdict, no half credit; same as Gate 3).
   Write the R1 table (Q, tier, expected -> got, verdict, reason, failure class) into this plan.
   Classes: (r) retrieval/ranking miss (the corpus holds the passage; check with a DB query and
   the mock chunk list), (s) answer shape or a required part missing, (b) wrong behavior choice,
   (c) corpus gap, (o) other.
4. **Triage and file fix issues.** Pick the fixes most likely to reach >= 21 by 2026-11-21.
   A fix is filed when it (a) has a named cause from step 3, (b) moves at least two failing
   questions or one tier-1 question, (c) has a pre-real-call check (mock eval/recall for
   retrieval, unit tests on prompt rendering for prompt changes), and (d) fits in about one day.
   Expected candidates, to be confirmed or dropped by R1 (Gate 3 evidence in brackets):
   - **F-ret (S1 area, retrieval ranking):** passages the corpus holds that are outside the
     per-firm pool or ranked below kept chunks (Gate 3: Q11, Q13, Q17, Q22, Q23, Q25; PR #202
     says ranking, not slots). Likely shape: count/benchmark rows (supplement advisor counts,
     NNA by quarter) reach the pool for benchmark questions. Check: must_return recall on the
     linked questions up, mock 30 no PASS -> FAIL, 0 forbidden, refusal unchanged.
   - **F-shape (S2 area, prompt/answer structure):** comparison questions answer on one common
     grid with empty cells shown as gaps (Q7, Q22); "spread of positions" questions organised by
     position (Q16); every part the question asks for is covered or named as a gap (Q3, Q12,
     Q19). General prompt rules only, no question-specific text; prompt version bump.
   - **F-behavior (S2 area, behavior choice):** partial evidence for the asked quantity ->
     `answer` with the missing parts as gaps (Q20, Q23); the asked quantity not disclosed ->
     `gap_with_adjacent` with the nearest disclosed quantity labelled (Q25). Likely the same
     issue and prompt version as F-shape if both are prompt-only.
   - **Corpus gaps (Q15 advisor-led revenue mechanism, Q20 under-40 surveys):** a new snapshot
     only if a public, cheap source fills one and still leaves time for R3 (one document, one
     snapshot build, one sync). Default: no new snapshot; listed as known gaps and in NEXT.md.
   Each filed issue: full `.github/ISSUE_TEMPLATE/task.yml` fields (Role TL, week W9, Why, Goal,
   Inputs, Deliverable, Acceptance with the linked question IDs, Verification, Out of scope,
   Depends on, Linked question IDs, Spec, Size), labels `role:tl` + type, added to the board in
   Todo, then the normal flow (`/start-task`, plan review, PR, review, merge). An ADR when a
   fix needs one (TL-approved). Their numbers go into "Depends on" below.
5. **Wait for the fixes to merge.** Rebase this branch on `main`; repeat step 1 (smoke, mock
   eval vs the committed baseline: no PASS -> FAIL unexplained, 0 forbidden, refusal unchanged).
   A fix that misses 2026-11-21 noon is left out of R3 and recorded as such.
6. **R3 final Gate 4 run.** Same command as step 2 with `--out ...\ev121\r3-real-30` on the
   merged `main` (this branch rebased; it changes no product code). Same checks.
7. **Score R3** as in step 3; Gate 4 table and X/30 (tier-1 split) in this plan, labelled
   "scored by the TL agent (Claude)". Post X/30 on #15 (Weekly score) and in the PR.
8. **Demo recording.** Write `scripts/record_demo.py` (step "Files to change"); dry run with the
   mock provider (0 calls), then one real take on three demo questions that show the three paths:
   a cited answer (Merrill's advisor strategy, the README example), a Merrill trap held
