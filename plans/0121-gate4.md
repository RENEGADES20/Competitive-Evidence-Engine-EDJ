**Rules.**
- At most one R2 run per bank question in total. The fix issues make **0 real calls on bank
  questions**: their pre-merge checks are mock eval/recall (retrieval) and unit tests on the
  rendered prompt and the Answer schema (prompt/behavior). The real check of all fixes together
  is the one combined R2. A fix issue that cannot be judged without a real call before merging
  gets questions assigned from the ledger by name, and those questions are then left out of R2.
- A wrong answer is a finding: no retry loop, no re-roll. `INVALID_OUTPUT` is kept (#187), not
  re-called.
- Demo questions are not bank questions (texts checked against `evals/questions.yaml` Q1-Q30):
  D1 "How does Merrill describe its Advisor Development Program for new advisors?" (cited answer),
  D2 "What was Merrill's revenue growth last year?" (Merrill trap: GWIM is not Merrill, caveat
  from code), D3 "How does LPL Financial recruit advisors?" (gap: LPL is mapped, not ingested).
  They are not in the bank ledger; their own cap is 2 runs each.
- Model = `LLM_MODEL` in `.env`, recorded by each run. Every raw output is kept in the run folder.

**Run ledger** (checked before every call; filled in after each run with called / reused /
no_call / invalid):

| Question | R1 | R2 | R3 | Total runs (max 3) |
|---|---|---|---|---|
| Q1-Q30, each | 1 (step 2) | 0 or 1 (step 5; list of IDs written here in step 4) | 1, or 0 if reused from cache | <= 3 |
| D1, D2, D3 | - | - | - | demo: <= 2 each |

The per-question rows (Q1 ... Q30) are written out in this table after R1, with the R2 column
filled in step 4 and the counts updated after R2 and R3.

   `repo\.venv`): `python -m cee.smoke` -> PASS; mock eval
   `scripts/eval_run.py --as-of 2026-11-17 --baseline evals/baselines/corpus-2026-11-17/report.json --out D:\ALLPROJECTS\EDJ\cache\ev121\mock-main`

   stops the plan until explained.
2. **R1 measure.** `$env:LLM_PROVIDER="anthropic"; PY scripts/eval_run.py --real --max-calls 30 --as-of 2026-11-17 --out D:\ALLPROJECTS\EDJ\cache\ev121\r1-real-30`
   (Mac: `LLM_PROVIDER=anthropic PY scripts/eval_run.py ...`; `.env` stays on mock). Check:
   calls + reused + no_call = 30, list INVALID_OUTPUT if any. Record sha, model, prompt version.
3. **Score R1.** Copy `pack.py` to `cache\ev121\pack.py`, build `cache\ev121\r1-scoring\`, read
   each answer against `passes_if` (four axes, one verdict, no half credit; same as Gate 3).
   Write the R1 table (Q, tier, expected -> got, verdict, reason, failure class) into this plan.
   Classes: (r) retrieval/ranking miss (the corpus holds the passage; check with a DB query and
   the mock chunk list), (s) answer shape or a required part missing, (b) wrong behavior choice,
   (c) corpus gap, (o) other.
4. **Triage and file fix issues.** Pick the fixes most likely to reach >= 21 by 2026-11-21.
   A fix is filed when it (a) has a named cause from step 3, (b) moves at least two failing
   questions or one tier-1 question, (c) has a pre-real-call check (mock eval/recall for
   retrieval, unit tests on prompt rendering for prompt changes), and (d) fits in about one day.
   Expected candidates, to be confirmed or dropped by R1 (Gate 3 evidence in brackets):
   - **F-ret (S1 area, retrieval ranking):** passages the corpus holds that are outside the
     per-firm pool or ranked below kept chunks (Gate 3: Q11, Q13, Q17, Q22, Q23, Q25; PR #202
     says ranking, not slots). Likely shape: count/benchmark rows (supplement advisor counts,
     NNA by quarter) reach the pool for benchmark questions. Check: must_return recall on the
     linked questions up, mock 30 no PASS -> FAIL, 0 forbidden, refusal unchanged.
   - **F-shape (S2 area, prompt/answer structure):** comparison questions answer on one common
     grid with empty cells shown as gaps (Q7, Q22); "spread of positions" questions organised by
     position (Q16); every part the question asks for is covered or named as a gap (Q3, Q12,
     Q19). General prompt rules only, no question-specific text; prompt version bump.
   - **F-behavior (S2 area, behavior choice):** partial evidence for the asked quantity ->
     `answer` with the missing parts as gaps (Q20, Q23); the asked quantity not disclosed ->
     `gap_with_adjacent` with the nearest disclosed quantity labelled (Q25). Likely the same
     issue and prompt version as F-shape if both are prompt-only.
   - **Corpus gaps (Q15 advisor-led revenue mechanism, Q20 under-40 surveys):** a new snapshot
     only if a public, cheap source fills one and still leaves time for R3 (one document, one
     snapshot build, one sync). Default: no new snapshot; listed as known gaps and in NEXT.md.
   Each filed issue: full `.github/ISSUE_TEMPLATE/task.yml` fields (Role TL, week W9, Why, Goal,
   Inputs, Deliverable, Acceptance with the linked question IDs, Verification, Out of scope,
   Depends on, Linked question IDs, Spec, Size), labels `role:tl` + type, added to the board in
   Todo, then the normal flow (`/start-task`, plan review, PR, review, merge). An ADR when a
   fix needs one (TL-approved). Their numbers go into "Depends on" below. Each issue says
   "0 real calls on bank questions; the real check is the combined R2 of #121" (Paid calls rules).
   In this step the R2 question list (targeted failing IDs + sentinels) is written into the
   ledger, and every bank question is checked to stay <= 3 runs before any R2 call.
5. **Wait for the fixes to merge, then R2.** Rebase this branch on `main`; repeat step 1 (smoke,
   mock eval vs the committed baseline: no PASS -> FAIL unexplained, 0 forbidden, refusal
   unchanged). Then one combined R2 in `wt-121`:
   `PY scripts/eval_run.py --real --questions <R2 IDs> --max-calls <n> --as-of 2026-11-17 --out ...\ev121\r2-real`.
   Score the R2 questions (step 3 method), update the ledger. If R2 shows a fix regressing a
   sentinel or not moving its targets, one correction PR on that fix issue is allowed before R3
   (its questions then get R3 as their third run, no further R2). A fix that misses
   2026-11-21 noon is left out of R3 and recorded as such.
6. **R3 final Gate 4 run.** Same command as step 2 with `--out ...\ev121\r3-real-30` on the
   merged `main` (this branch rebased; it changes no product code). Same checks. R1 and R2 ran in
   `wt-121`, so their outputs are in `wt-121\.eval-runs\cache\` and R3 reuses every question
   whose prompt version and retrieved chunks are unchanged, with no copying (outputs made in
   another worktree would not be reused, one more reason fix issues make no bank-question calls).
   Update the ledger (called / reused per question).
7. **Score R3** as in step 3; Gate 4 table and X/30 (tier-1 split) in this plan, labelled
   "scored by the TL agent (Claude)". Post X/30 on #15 (Weekly score) and in the PR.
8. **Demo recording.** Write `scripts/record_demo.py` (step "Files to change"); dry run with the
   mock provider (0 calls; check the exported rows say `mock`, and that the ffmpeg stop message
   appears with ffmpeg hidden from PATH), then one real take on D1-D3 (Paid calls: a cited
   answer, a Merrill trap held with the code-inserted GWIM caveat, an honest gap naming the
   missing LPL sources). Check after the take: 3 files in `cache\ev121\demo\raw\`, each
   with a non-mock model; at most one retake (cap 2 runs per demo question). Output:
   `cache\ev121\demo\gate4-demo.mp4` (full, also copied to Box `EDJ\results\`; the PR gives
   the Box path and the local file's size and sha256, since a reviewer cannot open Box),
   `docs/assets/gate4-demo.gif` (trimmed). This is a silent screen capture with
   on-screen captions, not a narrated video; a voiced walk-through needs a human, so RUN.md gets a
   2-minute script (what to click, what to say) for whoever records one.
9. **Results package.** Generate `docs/results/gate4-report.md` and `.json` from R3, write
   `docs/NEXT.md` from the remaining failures and the fixes not made, refresh `docs/RUN.md` and
   the README gate line.
10. **Verify and finish.** pytest (no product change, so unchanged), smoke PASS, `verify-cee`
    (the branch adds a script and docs only; run `doctor` and the `ask-answer` feature to prove
    the app used in the demo works), `/finish-task` with "Closes #121" if >= 21/30, otherwise
    "Part of #121" with the score and the open items (a failed gate means scope comes out, not
    that the gate moves: BRIEF).
