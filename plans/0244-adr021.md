## The 8 rules as ADR-021 will state them
1. **Behavior decided by code from the sub-questions** (code: #246 `EvidenceMatrix`; prompt v5 only
   writes): at least one firm x aspect holds the asked quantity -> `answer`, every missing firm x
   aspect named as a gap; none holds it but a different related quantity exists ->
   `gap_with_adjacent` with the difference stated in `differs_because`; nothing -> `refuse`
   (`answerable` false) with the gap "The database does not support this today: <aspect> (<firms>)."
   and suggested sources. Normative questions keep `answer_with_boundary` (existing code:
   `withhold_normative`, `ensure_handoff`; Q12, Q19); a request for the system's own forecast is
   `refuse`, attributed positions of others stay `answer` (Q16). Questions: Q11, Q23, Q25, Q28, Q24,
   Q29, Q30, Q22.
2. **Definitions from `config/metric_definitions.yaml`** (code: #246 comparability marks, caveat
   inserted by code like entity caveats; #247 number check on computed figures): compute only when
   both inputs share definition, period and unit, showing the formula and both cited inputs;
   otherwise list each firm's figure with its definition and a code-inserted comparability caveat
   (reporting risk); a metric not registered in the file is marked unverified, never assumed
   comparable. Questions: Q11, Q22, Q23, Q24.
3. **Adjacent is only for a different quantity** (code: #246 `different_quantity` vs fact; prompt
   v5): a partially covered asked quantity (some firms, some quarters, a narrower sample) is always a
   claim with its coverage stated. Wider units stay adjacent (GWIM for Merrill). Questions: Q25, Q11,
   Q23, Q28, Q29, Q30.
4. **Comparison questions carry one cited claim that answers the comparison itself** (prompt v5 +
   code check that a `kind=comparison` sub-question has it, #247). Questions: Q24 (Q15, Q10 checks).
5. **The "why it might matter" line** states only what the source says or a checkable fact, cited;
   never our judgement (ground rule 6; prompt v5; citation, number and normative checks by code,
   #247). Questions: Q26.
6. **Sub-question decomposition, literal**: the planner lists every aspect the question asks;
   code (not the LLM) sets the firms (resolved firms; for home-firm market questions the competitors
   as real entities, ADR-018); code expands firms x aspects, no merge, no cap; research searched once;
   every sub-question keeps all SQL filters; empty sub-questions get one corrective re-search (CRAG)
   with the exclude set (#245 hook, #246 use). Questions: Q19, Q11, Q24, Q1, Q3, Q22.
7. **ADR-012 amended: calls follow the decomposition**, no fixed number (planner 1 + map one per firm
   + research + re-extraction for re-searched sub-questions + reduce 1, map-reduce). Every question
   logs calls, input/output tokens and cost (cost from a configured price, #248); scored runs report
   them; scored and planned runs keep a run-level `--max-calls` (CLAUDE.md paid-call rule); the mock
   covers every call, tests and CI make 0 real calls. Quality first; cost reduction is later work.
   Questions: all.
8. **Bank conflict**: superseded expectations live in `evals/behavior_supersede.yaml` (scorer reads
   it in a later issue); appended questions pin the new rule; no question is rewritten. Questions:
   Q25 (+ Q24, Q28 per D2), Q31 (+ Q32 per D1).
