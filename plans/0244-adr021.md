## ADR-021 rules as they will be written
0. **Evidence only, never opinions** (overarching; ground rules 1, 4, 6). Every sentence of an answer
   is a cited fact from a stored chunk, a figure computed from cited inputs (rule 2), or a gap.
   Enforced by code: citation check, number check, `withhold_normative` / `ensure_handoff` (existing).
   Rules 1-8 apply it.
1. **Behavior.** Labels per firm x aspect cell (`fact`, `not_disclosed`, `not_found`,
   `different_quantity`) come from the map extraction call (extract-v1, #246, a prompt); **code**
   aggregates them into the behavior (#246 `EvidenceMatrix`), never the reduce call.
   (a) Question level: `answer` when any cell is `fact`; aspect level: every cell without a fact is a
   named gap, and an aspect that no asked firm holds gets "The database does not support this today:
   <aspect> (<firms>)." inside that answer.
   (b) No cell is a fact but some cell is `different_quantity`: `gap_with_adjacent`; the answer still
   states that the database does not support the asked quantity today, then the labelled adjacent
   figure with `differs_because`.
   (c) No fact and no related quantity: `refuse` (`answerable` false) with that gap and suggested
   sources.
   (d) Derived quantities: a quantity computable from same-firm cited inputs on the same basis (rule
   2, within-firm) counts as held (Q24's EDJ assets / advisors).
   (e) Precedence: a request for the system's own forecast -> `refuse`; else a normative part ->
   `answer_with_boundary` (existing code); else (a)-(c). Attributed positions of others are facts
   (Q16). Questions: Q11, Q22, Q23, Q24, Q25, Q28, Q29, Q30, Q31-Q35; Q12, Q19 (boundary).
2. **Definitions and comparability** (`config/metric_definitions.yaml`; code: #246 marks and
   caveats, #247 number check). Within-firm computation (a ratio, a sum): inputs share period/date,
   entity/segment scope and compatible units; formula and both cited inputs shown. Cross-firm
   comparison or computation: same definition, period and unit; otherwise each firm's figure is
   listed with its definition and the code-inserted comparability caveat (Standard wording). An input
   metric not registered in the file (e.g. client assets): computing is **allowed** within one firm
   when the within-firm test holds, with the "definition unverified" mark; cross-firm comparison of
   an unregistered metric is not made (listed only). Fields #246 adds to the file (C1 review):
   `period` (period basis: point in time / quarter / year), `unit`, `basis` (a key naming the
   definition, equal keys = same basis). Questions: Q11, Q22, Q23, Q24, Q31.
3. **Adjacent only for a different quantity** (label by extract-v1, #246; aggregation by code; prompt
   v5 writes it): a partially covered asked quantity (some firms, some quarters, a narrower sample) is
   a claim with its coverage stated; a wider unit or different measure (GWIM for Merrill, an industry
   survey for a firm) is adjacent. Questions: Q25, Q11, Q23, Q28, Q29, Q30, Q33-Q35.
4. **Comparison questions carry one cited claim answering the comparison itself** (prompt v5; code
   check for `kind=comparison`, #247). Questions: Q24 (Q15, Q10 checks).
5. **Why-it-might-matter line**: only what the source says or a checkable fact, cited; never our
   judgement (prompt v5; citation, number and normative checks by code, #247). Questions: Q26.
6. **Sub-question decomposition, literal** (planner prompt plan-v3 lists aspects; code sets firms and
   expands firms x aspects, #245): no merge, no cap; for home-firm market questions the competitors are
   real entities (ADR-018); research once; every sub-question keeps all SQL filters; an empty
   sub-question gets one corrective re-search (CRAG) with the exclude set (#245 hook, #246 use).
   Questions: Q19, Q11, Q24, Q1, Q3, Q22.
7. **Calls follow the decomposition (map-reduce), no fixed number**: planner 1 + map one per firm +
   research + re-extraction for re-searched sub-questions + reduce 1. Every question logs calls and
   input/output tokens; cost from a configured price (#248); scored runs report them and keep a
   run-level `--max-calls`; a plan states the expected count before real calls; the mock covers every
   call, tests and CI make 0 real calls. Quality first; cost reduction later. Questions: all.
8. **Bank conflict**: `evals/behavior_supersede.yaml` (scorer reads it from #248) supersedes Q24, Q25,
   Q28 to `answer`; Q31 pins partial disclosure is `answer`; Q32 pins `refuse`; Q33-Q35 pin
   `gap_with_adjacent`; no question is rewritten; the gap/refuse share is held on raw and effective
   behavior (6/35 effective).
